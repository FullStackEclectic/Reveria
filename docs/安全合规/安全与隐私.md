# 安全与隐私

## 安全原则

Reveria 会处理客户 brief、品牌资料、未发布素材、商业方案和模型 API key。这些数据对传媒工作室很敏感，因此安全和隐私必须从第一版开始设计。

原则：

- 第三方模型 key 永远不放在桌面端。
- 用户素材按工作区隔离。
- 高风险操作必须审计。
- 敏感数据最小化传递给上游模型。
- 支持后续私有化和 BYOK。

## 数据分类

### 用户身份数据

- 邮箱
- 手机号
- 昵称
- 登录设备
- 登录 IP

### 工作区数据

- 团队名称
- 成员列表
- 权限
- 套餐
- 点数余额

### 客户和品牌数据

- 客户名称
- 品牌资料
- logo
- 色板
- 字体
- 历史案例
- 商业 brief

### 创作数据

- prompt
- 生成结果
- 上传素材
- 分镜
- 脚本
- 导出文件

### 平台敏感数据

- 上游 API key
- 支付信息
- 点数流水
- 管理员操作日志
- 模型调用成本

## 密钥管理

上游模型 API key 必须：

- 服务端加密存储。
- 不进入桌面端。
- 不进入普通日志。
- 管理后台只显示掩码。
- 修改和查看写入审计日志。
- 支持定期轮换。

当前工程实现：

- 使用 `REVERIA_SECRET_KEY` 初始化服务端对称加密。
- provider API key 入库前会加密。
- API 响应不返回完整 API key。
- 开发环境未设置密钥时使用固定开发密钥，生产环境必须显式配置。

## 权限模型

建议采用工作区级 RBAC。

角色：

- owner：拥有全部权限。
- admin：管理成员、项目、点数和设置。
- manager：管理项目和客户。
- creator：创建和编辑内容。
- viewer：只读查看。

权限维度：

- 客户
- 项目
- 品牌库
- 素材
- 生成任务
- 点数
- 成员
- 管理后台

## 数据隔离

所有核心数据必须带 workspace_id。

要求：

- 查询必须校验 workspace 权限。
- 素材路径必须按工作区隔离。
- 生成任务不能跨工作区访问。
- 点数流水不能跨工作区展示。
- 管理员跨工作区操作必须审计。

## 上游模型隐私

调用第三方模型时，需要注意用户数据会发送给上游供应商。

建议：

- 在用户协议中说明数据处理方式。
- 对企业客户提供 BYOK。
- 对敏感项目提供禁用特定供应商选项。
- 尽量只发送完成任务所需的最小上下文。
- 不把完整客户资料无差别发送给所有模型。

## 本地数据

桌面端可能缓存素材和生成结果。

要求：

- 本地缓存目录明确。
- 支持清理缓存。
- 登录态安全存储。
- 不在本地保存上游模型 key。
- 敏感缓存后续可考虑加密。

## 内容合规

Reveria 应支持内容安全策略。

基础策略：

- 输入审核。
- 输出审核。
- 敏感词配置。
- 违规任务记录。
- 高风险内容人工复核。

不同市场可能需要不同策略，因此内容安全应做成可配置模块。

## 审计日志

必须审计：

- 登录异常
- 修改 API key
- 修改模型价格
- 手动补点
- 手动扣点
- 退款
- 导出客户数据
- 删除项目
- 禁用用户

审计日志应包含：

- 操作人
- 操作时间
- 操作对象
- 操作前后摘要
- IP
- user_agent

## 合规预留

后续可能需要支持：

- 数据导出
- 数据删除
- 企业私有化
- 区域化存储
- BYOK
- SSO
- 审计报表
- 数据保留周期配置
