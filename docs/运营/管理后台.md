# 管理后台

## 定位

Reveria 需要一个独立的 Admin Console，用来管理上游模型、积分体系、套餐权益、用户额度、工作流模板和运营风控。这个后台是积分制商业模式的基础。

Admin Console 不面向普通创作者，而面向平台运营、管理员、客服、财务和技术运维。

## 是否需要单独网站

需要一个管理后台，但它不一定一开始就是独立面向客户的网站。更推荐拆成两个界面：

- Reveria 工作台：给传媒工作室用户使用。
- Reveria Admin Console：给平台运营和管理员使用。

Admin Console 可以先做成内部管理页面，后续再扩展成完整的 SaaS 管理中心。

## 1. 模型供应商管理

用于配置所有上游模型供应商。

基础字段：

- provider_id
- provider_name
- provider_type
- base_url
- api_key
- region
- enabled
- priority
- timeout
- retry_policy
- rate_limit

供应商示例：

- ByteDance Doubao / Volcengine Ark
- Google Gemini
- xAI Grok
- OpenAI
- Anthropic Claude
- Azure OpenAI
- MiniMax
- Moonshot
- Zhipu
- Alibaba Qwen

## 2. 模型目录管理

用于维护平台可用模型列表。模型不应该只按供应商展示，而应该打上业务能力标签。

模型字段：

- model_id
- provider_id
- display_name
- capability
- context_window
- input_modalities
- output_modalities
- quality_tier
- latency_tier
- cost_tier
- enabled

能力标签：

- text
- reasoning
- vision
- image_generation
- image_editing
- video_generation
- audio_generation
- speech_to_text
- text_to_speech
- embedding

## 3. 模型路由规则

模型路由决定不同任务用哪个模型。

路由维度：

- task_type
- quality_mode
- user_plan
- workspace_region
- cost_limit
- provider_availability
- fallback_order

## 4. 点数定价规则

积分制不能只做简单固定扣点。不同模型和任务成本差异很大，后台需要可配置计价规则。

计价维度：

- input_token
- output_token
- image_count
- image_resolution
- video_seconds
- audio_seconds
- task_complexity
- priority_queue
- storage_usage
- workflow_steps

## 5. 套餐和权益

用于配置面向用户或团队的商业套餐。

套餐能力：

- 月度点数
- 额外点数包
- 并发任务数
- 云存储容量
- 可用模型等级
- 是否支持商用授权
- 是否支持团队成员
- 是否支持品牌库数量
- 是否支持私有模型 key
- 是否支持高级视频工作流

## 6. 用户和工作区额度

积分必须绑定到账户、团队、项目和成员。

需要支持：

- 工作区总余额
- 成员每日额度
- 项目预算
- 单任务最大消耗
- 高成本模型使用权限
- 自动停用异常账户
- 余额不足提醒
- 消耗日报和月报

- actual_credits

- error_code
- latency

- completed_at

任务状态：

- pending
- running
- succeeded
- failed
- refunded
- cancelled

## 8. 成本和毛利

Admin Console 必须让运营者知道每个模型、每个用户、每个项目是否赚钱。

关键指标：

- 用户充值金额
- 用户点数消耗
- 上游模型成本
- 项目毛利
- 模型毛利
- 供应商失败率
- 平均任务成本
- 平均任务耗时
- 退款率
- 异常消耗账户

当前 MVP 已实现工作区成本报表，入口在 Admin Console。报表按工作区聚合，不在桌面端本地计算，避免运营看到与账本不一致的数据。

已覆盖：

- 工作区成功任务实际消耗点数。
- 释放和退款点数。
- 项目成本排行，包含项目预算、累计消耗和任务数。
- 任务类型成本排行，包含预估点数、实际点数和任务数。
- 模型调用聚合，按供应商、模型、调用类型和状态统计调用次数、延迟和失败次数。
- 可归因上游成本 `provider_cost_micro`，用于后续毛利计算。

需要注意：当前上游模型成本只有在模型网关写入 `provider_cost_micro` 时才会显示真实数值；未回传成本时后台显示为未回传，不用点数收入倒推假成本。完整毛利报表还需要接入订单、充值、套餐赠点、供应商账单同步和币种汇率。

## 9. 工作流模板管理

Reveria 的工作流模板应该从后台发布，而不是写死在桌面端。

模板字段：

- template_id
- name
- task_type
- input_schema
- workflow_steps
- default_model_route
- pricing_rule
- enabled
- version

模板示例：

- 客户 brief 分析
- 品牌风格提取
- 三套创意方向
- 小红书封面批量生成
- 短视频脚本
- 分镜生成
- 视频封面生成
- 多平台尺寸导出

当前实现采用单活发布规则：同一个 `task_type` 只能有一个已发布版本。运营发布新版本时，旧版本会自动停用；任务执行会记录当时使用的 `template_id` 和 `template_version`，方便追溯效果和点数消耗。灰度发布、A/B 测试和回滚审批属于后续版本，不在第一阶段伪实现。

## 10. 风控和审计

因为上游模型调用会产生真实成本，必须有风控能力。

需要支持：

- 单用户频率限制
- 单工作区频率限制
- 单 IP 频率限制
- 高成本任务二次确认
- 异常消耗自动冻结
- API key 泄露检测
- 敏感内容策略
- 管理员操作审计
- 退款和补点审计

## 11. 内部运营工具

为了快速迭代产品，后台还应包含运营工具。

可选能力：

- 模型 A/B 测试
- prompt 版本测试
- 模板发布灰度
- 用户反馈标注
- 失败任务重跑
- 手动补点
- 客服查看用户任务上下文
- 供应商余额预警

## 最小后台版本

MVP 不需要一次性实现完整 Admin Console，但必须先实现以下功能：

- 平台管理员列表、授权和撤销
- 供应商和 API key 配置
- 模型列表
- 模型启用和禁用
- 图片生成模型测试
- 工作流模板配置
- 基础点数定价
- 用户余额
- 点数流水
- 成本报表
- 任务状态
- 失败退款
- 管理员手动补点

当前实现说明：后台使用统一邮箱密码账号和 Bearer session 登录；第一位成功注册或开发登录用户会在系统无管理员时自动成为平台管理员。后台已支持平台管理员授权和撤销，并保护最后一个平台管理员不被撤销。成本报表接口允许平台管理员或工作区 `owner/admin` 查看，普通成员不能访问。
