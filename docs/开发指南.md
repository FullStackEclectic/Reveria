# Reveria 开发者指南

欢迎加入 Reveria 项目开发！本项目是一套服务于传媒工作室的 AI 创意生产交付平台。

整个工程的核心业务、项目管理及画布逻辑由云端 Go API 承载，Wails 桌面端作为云端客户端运行。本机只负责素材缓存、文件导出和原生图像处理，不维护项目、账户、计费等主业务数据库；只有未来明确出现离线元数据需求时，桌面端才引入 SQLite。

桌面端开发或构建前必须配置 `VITE_REVERIA_API_BASE`，其值为目标云端 API 根地址。本地联调时也可以指向本机启动的 API 服务。

---

## 🛠️ 本地开发环境准备

请在开始开发前，确保你的本地开发机已准备好以下基础环境：

1. **Go (1.21+)**：用于编写后端服务分站及桌面外壳底座。
2. **Node.js (18+) & pnpm (v9+)**：用于运行和构建前端大单体及 Next.js 网页。
3. **Wails CLI**：Wails 框架自带的命令行工具，用于调试和打包桌面端。
   ```powershell
   # 安装 Wails 命令行工具
   go install github.com/wailsapp/wails/v2/cmd/wails@latest
   ```
4. **Rust & Cargo (1.70+)**（可选）：仅在需要修改或重新编译底层原生图像处理引擎 `native-engine` 时需要。

---

## 📦 依赖初始化

在项目根目录下，直接执行 `pnpm install`。pnpm 会自动扫描并在工作区（`apps/*`、`packages/*`）之间建立正确的代码软链接：
```powershell
pnpm install
```

---

## 🦀 Rust 原生引擎编译 (可选)

系统附带了已经编译好的 `native_engine.dll`，默认情况下无需手动编译。如果你修改了 `packages/native-engine` 中的 Rust 算法，可以通过以下命令重新编译：
```powershell
cd packages/native-engine
cargo build --release
```
编译后的动态链接库会自动生成在 `packages/native-engine/target/release/native_engine.dll`，Go 后端在启动时会自动检测并加载该路径下的 DLL。

## 🚀 启动本地服务

本地开发联调时，通常需要分三步启动对应的服务：

### 🏁 第一步：启动 Go 后端 API 服务
进入后端目录，运行 API 服务。
```powershell
cd services/api
go run main.go
# 默认监听在 http://127.0.0.1:4100
```
* **数据库免配置**：后端采用纯 Go 版本的 SQLite 驱动（`github.com/glebarez/sqlite`），启动时会自动在 `services/api/` 目录下创建 `reveria.db` 文件，并自动执行 GORM 表结构迁移。**你不需要本地运行 PostgreSQL 或拉起 Docker 容器。**
* **接口前缀**：所有业务接口前缀为 `/api`。后端全局注册了 `/api/v1/*any` 的重定向层，自动兼容旧版的接口调用。

### 💻 第二步：拉起桌面开发视窗 (Wails)
进入桌面目录，使用 Wails 工具链拉起测试客户端：
```powershell
cd apps/desktop
wails dev
```
* **工作原理**：Wails 会拉起位于 `1420` 端口的前端 Vite 热重载服务，并调起系统原生的 WebView2 容器，在桌面上弹出 Reveria 客户端窗口。
* **无干扰开发**：你也可以在普通浏览器中直接访问 **`http://localhost:1420`** 或 Wails 的绑定调试端口 **`http://localhost:34115`** 进行无窗口调试。

### 🌐 第三步：拉起网页版 (Next.js) & 商业管理后台
网页版可用于普通用户浏览器访问，同时提供了商业版专用的独立控制台。
```powershell
cd apps/web-next
pnpm dev
# 默认监听在 http://localhost:3000
```
* **主页访问**：`http://localhost:3000`。
* **超管独立控制台**：**`http://localhost:3000/admin`**。

## 🔐 授权与超级管理员开发登录

为了极大简化本地开发和功能测试过程，系统做出了如下鉴权设计：

1. **开发一键登录**：
   * 在客户端/网页的登录界面上，点击 **“开发模式登录”** 按钮。
   * 该操作会向后端 `/api/auth/dev-login` 提交免密登录请求。后端会自动为你创建或登入开发版超级管理员账号，同时在账户中赠送 `100,000` 点初始算力额度。
2. **Token 会话认证**：
   * 登录成功后，前端会把 JWT 写入浏览器的 `localStorage` 中。
   * 所有敏感的写接口（如创建项目、工作流触发、后台算力配置）均需在 Header 中携带 `Authorization: Bearer {token}`。Go 后端会在 JWT 拦截器中严格校验用户角色，拦截越权行为。

## 🎨 前端 Monorepo 开发说明

项目中的前端代码使用 Monorepo 进行组织管理，避免双端重复写代码：

* **核心共享包 (`packages/shared`)**：
  * 画布交互、侧栏导航、财务账本、以及素材网格等所有核心业务组件及数据请求全部位于此处。
  * `AppCore.tsx` 是主业务组件；各功能面板（如 `AdminView`, `DashboardView`）位于 `components/` 目录下。
* **即时热更新 (HMR)**：
  * 桌面端的 `vite.config.ts` 配置了对 `packages/shared` 源码绝对路径的 Alias 解析，你在共享包里修改任何 TSX 源码，桌面窗口和浏览器内都会**即时热重载**，不需要任何多余的编译打包等待。
* **SSR 安全防线**：
  * 因为网页端（Next.js）是在服务器端预渲染（SSR）的，所以我们在共享包里使用 `localStorage` 等浏览器全局对象时，**必须先判断 `typeof window !== "undefined"`**，否则会导致 Next.js 编译崩溃。

## 📦 生产发布与归档

1. **发布桌面端安装包**：
   ```powershell
   cd apps/desktop
   wails build
   # 会在 apps/desktop/build/bin 目录下产出无多余依赖的单体 Reveria.exe 文件
   ```
2. **发布网页端与云端后台**：
   ```powershell
   cd apps/web-next
   pnpm build
   # 输出用于 Node.js 服务器或 Vercel 部署的生产资源
   ```
