# 积分系统与计费

账本在分站 Go API（正式环境 PostgreSQL），Web / 桌面端只调 API。不要在客户端再做一套积分库。

## 核心判断

积分系统是 Reveria 的核心业务能力，不能完全交给模型网关或第三方计费工具。NewAPI、LiteLLM、OpenMeter、Lago 等工具可以辅助模型中转、用量计量或账单管理，但 Reveria 必须自己掌握积分账本。

积分制的目标不是简单扣点，而是：

- 控制上游模型成本。
- 支持不同套餐权益。
- 让用户理解每次任务消耗。
- 支持失败退款。
- 支持项目预算和成员额度。
- 统计客户项目毛利。

## 基础概念

- account：账户或团队。
- workspace：工作区。
- user：成员。
- project：项目。
- credit_balance：当前点数余额。
- credit_transaction：点数流水。
- usage_event：模型调用或生成任务消耗事件。
- pricing_rule：不同模型和任务的计价规则。
- frozen_credit：任务执行前冻结的点数。

## 账本原则

- 所有点数变化必须产生流水。
- 流水不可随意删除，只能通过反向流水修正。
- 任务执行前先预估和冻结点数。
- 任务完成后按实际消耗结算。
- 任务失败后按失败原因全额或部分退款。
- 管理员补点、扣点、退款都必须记录操作人和原因。

## 积分结算流程

每次生成任务应按以下流程处理：

```text
1. 用户选择任务，例如生成 9 张小红书封面。
2. 服务端根据模型、数量、尺寸和质量预估点数。
3. 如果余额不足，拒绝任务并提示充值。
4. 如果余额足够，冻结预估点数。
5. Task Orchestrator 调用 Model Gateway。
6. Model Gateway 调用具体模型供应商。
7. 任务完成后记录实际 token、图片数、视频秒数或模型费用。
8. Credit Ledger 按实际消耗扣点。
9. 多冻结的点数退回。
10. 任务失败则全部或部分退款。
```

## 计价维度

积分制不能只做简单固定扣点。不同模型和任务成本差异很大，后台需要可配置计价规则。

计价维度：

- input_token
- output_token
- image_count
- image_resolution
- video_seconds
- audio_seconds
- task_complexity
- priority_queue
- storage_usage
- workflow_steps

## 点数规则示例

```text
基础文案生成：按 token 成本加服务费换算点数。
高清图片生成：按图片张数、尺寸和模型质量扣点。
视频生成：按秒数、分辨率、模型和并发等级扣点。
批量任务：按子任务数量结算，可设置折扣。
失败任务：按失败原因全额或部分退款。
```

## 套餐和权益

用于配置面向用户或团队的商业套餐。

套餐能力：

- 月度点数
- 额外点数包
- 并发任务数
- 云存储容量
- 可用模型等级
- 是否支持商用授权
- 是否支持团队成员
- 是否支持品牌库数量
- 是否支持私有模型 key
- 是否支持高级视频工作流

## 用户和工作区额度

积分必须绑定到账户、团队、项目和成员。

需要支持：

- 工作区总余额
- 成员每日额度
- 项目预算
- 单任务最大消耗
- 高成本模型使用权限
- 自动停用异常账户
- 余额不足提醒
- 消耗日报和月报

## 成本和毛利

积分系统不仅服务用户侧扣点，也服务平台运营和工作室经营。

关键指标：

- 用户充值金额
- 用户点数消耗
- 上游模型成本
- 项目毛利
- 模型毛利
- 供应商失败率
- 平均任务成本
- 平均任务耗时
- 退款率
- 异常消耗账户

## 不推荐的方案

- 在桌面端写死第三方模型 key。
- 把所有积分逻辑交给 NewAPI 或 LiteLLM。
- 只按请求次数扣点，不记录真实模型成本。
- 允许客户端直接请求第三方模型。
- 没有冻结、结算和退款机制。
