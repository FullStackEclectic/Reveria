# 用户体验与桌面端设计

## 设计目标

Reveria 的桌面端应该像工作室的生产台，而不是模型参数控制台。用户打开后应该直接看到项目、客户、素材、任务和交付状态。

体验关键词：

- 清晰
- 稳定
- 可控
- 适合批量生产
- 适合长时间工作
- 适合团队交付

## 信息架构

建议桌面端采用三层结构：

```text
左侧导航：工作区、项目、客户、品牌库、素材库、模板、点数
中间主区：当前项目、画布、任务流、生成结果
右侧面板：品牌上下文、参数、点数预估、版本和导出
```

## 首页

首页不做营销式 landing page，而是直接进入工作台。

首页应该展示：

- 最近项目
- 待处理任务
- 最近生成
- 点数余额
- 快速创建项目
- 常用工作流模板

## 项目页

项目页是核心页面。

建议模块：

- 项目 brief
- 品牌上下文
- 素材区
- 创意方向
- 生成任务
- 交付版本
- 点数消耗
- 修改记录

## 品牌库体验

品牌库应该像客户记忆，而不是普通文件夹。

用户上传素材后，系统应自动分析：

- 主色
- 辅助色
- 字体风格
- 画面构图
- 文案口吻
- 常见禁忌
- 可复用风格描述

用户可以手动确认或修改分析结果。

## 生成任务体验

用户不应该先选模型，而应该先选任务。

任务入口示例：

- 生成创意方向
- 生成封面
- 生成海报
- 扩写文案
- 改成另一种风格
- 生成短视频脚本
- 生成分镜
- 导出多平台尺寸

每个任务执行前展示：

- 输入摘要
- 使用品牌库
- 预估点数
- 预计耗时
- 输出数量

## 点数展示

点数展示必须透明，但不能干扰创作。

建议规则：

- 高成本任务执行前强提示。
- 普通任务只轻量展示预估点数。
- 任务完成后在结果卡片显示实际点数。
- 项目页显示本项目累计消耗。
- 工作区显示剩余额度和本月消耗。

## 画布策略

MVP 不需要完整无限画布，但应该预留画布能力。

第一阶段可以采用无限画布：

- 结果对比
- 图片排列
- 版本标注
- 简单批注
- 尺寸预览

当前第一阶段实现为项目无限画布：项目详情页可从当前项目素材中添加素材卡片，也可以添加备注卡片；卡片支持拖动位置并保存到服务端 `project_canvases`。这用于整理交付思路、对比候选图和记录修改意见，不承诺完整设计编辑、图层系统或无限画布。

第二阶段再加入：

- 多元素编辑
- 文本层
- 图片层
- 参考图固定
- 多尺寸画板
- 简单协作批注

## 任务状态

生成任务必须有明确状态，避免用户不知道系统是否卡住。

状态：

- 排队中
- 生成中
- 正在优化
- 成功
- 失败
- 已退款
- 已取消

失败时应该展示：

- 简明原因
- 是否扣点
- 是否已退款
- 是否可以重试

## 导出体验

导出是工作室的终点，不是附属功能。

应支持：

- 单图导出
- 批量导出
- 按平台尺寸导出
- 项目交付包
- 文案和脚本导出
- 生成记录导出

后续可支持：

- PSD
- PPTX
- MP4
- ZIP 交付包
- 客户预览链接

## 桌面端特性

桌面端应利用本地能力：

- 本地素材缓存
- 拖拽上传
- 剪贴板导入图片
- 文件夹导入
- 本地导出目录
- 任务完成系统通知
- 网络中断后的任务恢复

## 不推荐的体验

- 默认展示模型供应商列表。
- 默认展示复杂节点图。
- 把点数扣费隐藏起来。
- 生成失败后只显示技术错误。
- 首页做成宣传页。
- 让用户先理解参数再完成任务。
