# Reveria 前端设计与视觉规范

本规范旨在为 Reveria 桌面端（Wails + React）的前端开发提供统一的视觉指引和样式编写标准，以确保软件界面具有专业创意生产软件（如 Figma, Linear 等）的高品质质感。

---

## 1. 核心设计理念

Reveria 桌面端定位为**“创意工作室的生产台，而非模型参数控制台”**。为了让用户在长时间的生产交付工作中保持高效、愉悦，界面视觉应遵循以下三个原则：

- **深度层级与物理质感**：利用多层复合微阴影和磨砂玻璃边框高光，创造清晰的视觉层级与三维景深，杜绝廉价的扁平化与粗糙大边框。
- **克制且优雅的配色**：主色调选用高雅的**墨绿色/青色 (Teal)**，结合温暖自然的**米白色 (Warm Beige)**，局部搭配高亮白透磨砂材质，营造典雅、专注的创作氛围。
- **灵动的微交互 (Micro-interactions)**：界面应该是有呼吸感的。所有的悬停 (Hover)、点击 (Active)、弹窗和切换都必须配合柔和的贝塞尔过渡曲线，提供物理级别的顺滑反馈。

---

## 2. Design Tokens (视觉变量)

所有样式编写必须基于以下定义的 CSS 变量（存放在 `styles.css` 的 `:root` 中），禁止在业务组件内随意书写硬编码颜色和魔数。

### 2.1 颜色系统 (Color System)

| 变量名 | 推荐色值 | 描述与使用场景 |
| :--- | :--- | :--- |
| `--rv-color-bg-base` | `hsl(45, 12%, 94%)` (`#f3f2ee`) | 软件全局底部背景色，温暖沉静的米白底色 |
| `--rv-color-bg-sidebar`| `hsl(45, 14%, 97%)` (`#fbfaf7`) | 侧边栏与导航背景，略浅于全局底色 |
| `--rv-color-bg-panel` | `rgba(255, 254, 250, 0.8)` | 标准面板/卡片背景，带 80% 不透明度的乳白 |
| `--rv-color-bg-glass` | `rgba(255, 255, 255, 0.7)` | 弹出框、高光悬浮窗背景，白色半透明磨砂材质 |
| `--rv-color-border-thin`| `rgba(185, 178, 165, 0.35)` | 极细的中性边框，用于面板分割 |
| `--rv-color-border-glass`| `rgba(255, 255, 255, 0.6)` | 玻璃态卡片边缘高光描边，创造高光折射感 |
| `--rv-color-text-main` | `hsl(220, 13%, 12%)` (`#1c1d21`) | 核心正文、标题颜色，高对比深炭灰色 |
| `--rv-color-text-muted`| `hsl(30, 6%, 42%)` (`#736f6a`) | 辅助文案、说明文案颜色，温和的中性灰色 |
| `--rv-color-primary` | `hsl(172, 76%, 25%)` (`#0f766e`) | 主品牌色（Teal），用于主按钮、核心高亮项 |
| `--rv-color-primary-hover`| `hsl(172, 70%, 20%)` (`#0a524c`) | 主品牌色悬停态 |
| `--rv-color-primary-light`| `rgba(15, 118, 110, 0.08)` | 浅青色背景，用于选项激活态、输入框聚焦阴影 |

### 2.2 多层复合微阴影 (Multi-layered Shadows)

避免使用生硬、单一的粗糙阴影，通过双层甚至三层阴影叠加，模拟真实的自然环境漫反射：

```css
/* 极小阴影：适用于按钮、输入框 */
--rv-shadow-sm: 0 1px 2px rgba(0, 0, 0, 0.04);

/* 中度阴影：适用于标准卡片、小面板 */
--rv-shadow-md: 
  0 4px 6px -1px rgba(17, 24, 39, 0.03), 
  0 2px 4px -1px rgba(17, 24, 39, 0.02);

/* 重度阴影：适用于大面板、侧滑面板、悬浮卡片 */
--rv-shadow-lg: 
  0 10px 20px -3px rgba(17, 24, 39, 0.06), 
  0 4px 8px -2px rgba(17, 24, 39, 0.03);

/* 顶级阴影：适用于模态弹窗、全局大图预览灯箱 */
--rv-shadow-xl: 
  0 20px 32px -4px rgba(17, 24, 39, 0.1), 
  0 8px 16px -4px rgba(17, 24, 39, 0.05);
```

### 2.3 间距与圆角 (Spacing & Radius)

- **间距基阶**：采用 4px 的倍数阶梯（`4px`, `8px`, `12px`, `16px`, `20px`, `24px`, `32px`）。
- **圆角规范**：
  - `4px` (`--rv-radius-xs`)：非常小的标签、指示器。
  - `8px` (`--rv-radius-sm`)：输入框、普通按钮、缩略图。
  - `12px` (`--rv-radius-md`)：标准卡片、侧栏选项。
  - `16px` (`--rv-radius-lg`)：模态框、核心控制面板。

## 3. 界面质感与组件样式标准

### 3.1 玻璃拟态 (Glassmorphism) 卡片

当卡片或面板叠加在其他内容上方时（如弹窗、右侧浮动属性栏），必须使用玻璃拟态：

```css
.rv-glass-panel {
  background: var(--rv-color-bg-glass);
  backdrop-filter: blur(12px) saturate(110%);
  -webkit-backdrop-filter: blur(12px) saturate(110%);
  border: 1px solid var(--rv-color-border-glass);
  border-radius: var(--rv-radius-md);
  box-shadow: var(--rv-shadow-lg);
}
```

### 3.2 质感按钮与输入框

- **主按钮 (Primary Button)**：
  - 不能仅是一个单纯的扁平色块。按钮应该有微弱的渐变，Hover 时产生柔和发光感，Active 时有稍微按压下去的触感反馈。
- **输入框 (Input / Textarea)**：
  - 默认状态下拥有细腻的内描边；Focus 状态时，描边变为主色（Teal），同时获得一层淡青色的发光外阴影（`box-shadow: 0 0 0 3px rgba(15, 118, 110, 0.15)`），且过渡时间须达到 180ms。

### 3.3 自定义极细滚动条

原生系统的滚动条非常粗糙且占用空间。Reveria 中所有的可滚动区域均须定制为极细、淡雅且圆润的滚动条：

```css
.scrollable-container::-webkit-scrollbar {
  width: 6px;
  height: 6px;
}
.scrollable-container::-webkit-scrollbar-track {
  background: transparent;
}
.scrollable-container::-webkit-scrollbar-thumb {
  background: rgba(115, 111, 106, 0.2);
  border-radius: 3px;
}
.scrollable-container::-webkit-scrollbar-thumb:hover {
  background: rgba(115, 111, 106, 0.4);
}
```

## 4. 交互微动效指引

微动效是专业软件的核心魅力所在。组件的交互需要平滑自然：

- **统一过渡属性**：
  ```css
  transition: 
    background-color 0.2s cubic-bezier(0.4, 0, 0.2, 1),
    border-color 0.2s cubic-bezier(0.4, 0, 0.2, 1),
    box-shadow 0.2s cubic-bezier(0.4, 0, 0.2, 1),
    transform 0.2s cubic-bezier(0.4, 0, 0.2, 1);
  ```
- **悬停浮起反馈**：卡片在鼠标悬停时，应用向上偏移 2px，并加深阴影，暗示其可交互性。
- **点击按压反馈**：在鼠标按下瞬间，组件应用微缩放效果（如 `transform: scale(0.98)` 或 `translateY(1px)`）。

## 5. 前端重构与开发约束

1. **单文件代码量硬限制**：
   - 保持 React 组件的原子性。单个文件的代码行数原则上**不得超过 800 行**。如果发现文件过大，应当立即按照视图 (View)、容器 (Container) 和原子 UI 级组件进行重构拆分。
2. **严禁硬编码**：
   - 系统开发时**不允许使用硬编码数据和模拟数据**。所有页面所需的数据（项目、品牌、额度等）必须走 API 与数据库联通。测试功能时可在本地数据库注入测试记录。
