# 图像精修工作台

## 产品定位

图像精修工作台是 Reveria 桌面端内置的图像后期处理模块。它**不对标 Photoshop** 的专业图层/矢量/排版设计能力，而是对标**像素蛋糕、泼辣修图、美图秀秀**这类轻量易用的移动端/桌面端修图产品。

**定位一句话**：AI 生图之后的最后一公里——让工作室在不离开 Reveria 的情况下，完成素材的人像美化、色彩调校、瑕疵修复和风格润色，直接交付客户。

### 与竞品的参照关系

| 竞品 | 核心优势 | 我们借鉴的点 |
|------|---------|------------|
| 像素蛋糕 | 商业人像专业磨皮、中性灰修肤、批量处理 | 像素级磨皮精度、面部关键点美型、批量流水线 |
| 泼辣修图 | 专业色彩调校体系、预设生态、局部蒙版编辑 | HSL/曲线/色调映射调色体系、画笔/渐变/颜色蒙版局部调色、预设保存与分享机制 |
| 美图秀秀 | 消费级易用、一键美颜、AI 智能工具丰富 | 操作简洁、快速美颜（磨皮/美白/瘦脸/大眼）、一键滤镜、AI 变清晰、消除笔上手体验 |

## 架构决策

### 已确定：Capacitor + WebGL 方案

**多端渲染层选择：WebGL（不换框架）**

WebGL 在所有目标端均原生支持：
- 桌面端 Wails：Go 内嵌 WebView，WebGL 直接可用
- 网页端 Next.js：浏览器原生支持
- 未来手机端 Capacitor：iOS WKWebView / Android WebView，WebGL 同样支持

图像精修工具处理的是单张静态图，不是实时游戏渲染，Capacitor WebView 的性能完全够用。泼辣修图移动端本身也走的是此路线。

**未来移动端扩展路径：`apps/mobile`（Capacitor）**

```
apps/
  web-next/    ← Next.js 网页端（已有）
  desktop/     ← Vite + Wails 桌面端（已有）
  mobile/      ← 未来：Capacitor 包装 web-next，零代码改动
```

### 核心约定：RetouchSettings 是唯一真相来源

所有影响图像渲染的参数**必须**通过 `RetouchSettings` 传递，不允许存在平行的本地状态来控制渲染结果。

当前已实现（Shader 直接计算）：
- 光影：曝光、对比度、高光、阴影、白色色阶、黑色色阶
- 色彩：饱和度、自然饱和度、色温、色调、去朦胧
- 细节：清晰度、锐化
- 人像：磨皮（双边滤波）、美白（肤色区域提亮）
- 分色：HSL 八通道色相、饱和度、明度
- 曲线：主 RGB 与红/绿/蓝单通道五点曲线，GPU 分段线性映射
- 色调映射：阴影/高光独立色相与饱和度、明暗平衡
- 局部修复：污点画笔邻域纹理采样与羽化融合，每张图片最多保留 16 个修复点
- 仿制图章：源点取样、目标区域相对位移复制与羽化覆盖，每张图片最多保留 12 个图章
- 面部增强：基于 MediaPipe Face Mesh 的大眼、瘦脸与眼白选择性亮眼

`PortraitAdjustments` 中除磨皮、美白、大眼、瘦脸之外的祛斑、液化和面部精调参数仍是 UI 交互预留，尚未接通 Shader。

### 渲染组件结构

```
AssetEditorWorkbench    ← 状态管理 + UI 交互（不含 WebGL 代码）
        │
        └── RetouchRenderer   ← 纯渲染（只接收 imageUrl + settings + showOriginal）
                               内部：Shader 编译一次缓存，参数变化只更新 uniform
```

`RetouchRenderer` 是可替换的渲染实现层。未来如需迁移到 react-native-skia，只替换这一个组件。

## 技术方案

### 渲染引擎

当前已有：基于 WebGL GLSL Shader 的实时渲染管线（`editorConstants.ts`），支持曝光/对比度/饱和度/双边滤波磨皮。

扩展方向：
- **色彩调校**（曲线、色温、HSL）：在现有 Shader 管线中增加参数 uniform，全部在 GPU 实时计算，无需后端。
- **人脸识别关键点**（瘦脸/大眼/美白）：使用 [MediaPipe Face Mesh](https://mediapipe.dev/solutions/face_mesh)（纯前端 WASM，不上传数据）或接入 Rust 原生引擎（`packages/native-engine`）。
- **局部修复/仿制图章**：Canvas 2D API 实现基本能力；高质量内容感知填充可调用云端 AI API（无需本地算法）。
- **局部蒙版调色**：最多 6 个蒙版共享一张 3×2 画笔图集；线性、径向、颜色和亮度蒙版在 Shader 中解析计算，每个蒙版独立上传调色参数并按顺序叠加。
- **智能消除/抠图**：已确定统一对接上游 AI 图像编辑 API，走现有任务队列、计费与素材归档。抠图结果必须是带透明像素且保持源图宽高比的 PNG；暂不引入 u2net/ONNX Runtime Web，避免显著增加前端包体与移动端内存占用。

### 前端架构

- 主组件：`packages/shared/src/components/asset/AssetEditorWorkbench.tsx`
- WebGL 渲染：`packages/shared/src/components/asset/RetouchRenderer.tsx`
- 人像参数：`packages/shared/src/components/asset/PortraitAdjustments.tsx`
- 色彩参数：`packages/shared/src/components/asset/ColorAdjustments.tsx`
- 常量/Shader：`packages/shared/src/components/asset/editorConstants.ts`

操作历史（撤销/重做）：维护最多 50 步参数快照，不做像素级历史，仅记录参数状态。

素材修图参数通过后端 `advanced_json` 保存完整 `RetouchSettings`，同时保留旧基础字段以兼容已有数据。进入工作台或切换素材时自动拉取并恢复参数。

### 预设持久化

自定义预设保存在用户账号下，并在浏览器 `localStorage` 保留离线缓存。旧本地预设会在登录后自动迁移；离线创建的预设会在恢复连接后同步。

### Rust 原生引擎（`packages/native-engine`）

高计算量的本地算法（批量导出、高精度磨皮）放在 Rust DLL，通过 Go 桌面端 syscall 调用。MediaPipe WASM 方案可先行，后续迁移至 Rust 引擎以提升性能。
