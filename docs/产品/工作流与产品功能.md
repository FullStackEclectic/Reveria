# 工作流与产品功能

## 产品原则

Reveria 的产品体验应该围绕真实工作室交付，而不是围绕模型参数。

普通用户看到的是：

- 生成一套小红书封面
- 按品牌风格重做
- 扩展成 9 张图文
- 改成 618 活动版
- 生成三套客户提案方向
- 导出不同平台尺寸

这些动作背后可以由复杂工作流完成，但用户不需要直接操作节点。

## 核心工作流

Reveria 的第一个杀手级流程应该是从客户 brief 到交付包。

```text
客户 Brief
  -> 自动整理项目目标、受众和限制
  -> 读取客户品牌库和历史案例
  -> 生成 3 套创意方向
  -> 每套方向生成主视觉、封面、脚本和分镜
  -> 用户选择一个方向继续扩展
  -> 批量生成多平台尺寸和文案版本
  -> 团队修改、版本管理和客户审批
  -> 导出交付包
  -> 自动统计本项目点数成本
```

## 项目制

项目是 Reveria 的基本生产单位。

项目应包含：

- 客户
- 项目 brief
- 目标平台
- 截止时间
- 品牌资料
- 参考素材
- 生成历史
- 交付版本
- 修改意见
- 点数消耗
- 成本和毛利

## 品牌库

每个客户都应该拥有长期可复用的品牌上下文。

品牌库应包含：

- logo
- 色板
- 字体
- 视觉风格
- 文案口吻
- 禁用词
- 历史案例
- 爆款参考
- 客户偏好
- 常用尺寸
- 交付格式

之后所有图片、视频、文案、封面和提案都自动继承这些上下文。

## 图文视频一体化

用户不应该被迫先选择作图工具或视频工具。真实任务通常是一次活动、一组投放或一个客户交付。

一个项目可以同时产出：

- 主视觉
- 社媒封面
- 活动海报
- 短视频脚本
- 分镜
- 口播稿
- 视频封面
- 发布标题
- 平台文案
- 多尺寸导出包

## 批量生产

中小传媒工作室真正的痛点不是生成一张好看的图，而是在稳定风格下批量交付。

关键流程：

- 一键生成多套创意方向。
- 一套方向扩展成多张图文。
- 同一素材适配多个平台尺寸。
- 同一脚本生成多个封面和标题版本。
- 同一品牌风格复用到多个项目。

## MVP 功能

第一版应优先验证工作室用户是否愿意围绕 Reveria 管理项目和消耗点数。

MVP 功能：

- 跨平台桌面端
- 登录和工作区
- 项目管理
- 客户和品牌资料库
- 素材库
- AI 文案生成
- AI 图片生成与改图
- 生成历史
- 基础点数账本
- 主流大模型 API 接入
- 3 到 5 个固定工作流模板

建议优先实现的模板：

- 客户 brief 分析
- 品牌风格提取
- 三套创意方向
- 小红书封面批量生成
- 短视频脚本和分镜

## 第二阶段

- 画布编辑器
- 多尺寸批量出图
- 团队成员与权限
- 项目级预算和消耗统计
- 更完整的模板系统
- 后台生成 worker
- 生成任务队列
- Prompt、模型调用和成本观测

## 第三阶段

- 高级工作流编辑器
- 私有化部署
- 本地 GPU worker
- 客户审批流程
- 多人协作
- 插件系统
- 模板市场
- 更完整的账单、套餐和发票能力

## 工作流编辑器策略

Reveria 不应该把工作流编辑器作为 MVP 的核心入口。早期应优先提供固定工作流模板。

当固定模板验证稳定后，再为高级用户、内部运营人员或插件开发者开放工作流编辑器。

推荐顺序：

1. 普通用户使用模板化入口。
2. 内部运营配置工作流模板。
3. 高级用户使用可视化工作流。
4. 第三方开发者通过 API 或插件调用工作流。
