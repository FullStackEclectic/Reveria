# 工作流模板规格

## 定位

工作流模板是 Reveria 对 Lovart Skills 和 LibTV Skill/API 的吸收和重构。普通用户通过模板完成高频任务，内部运营通过后台配置模板，高级用户和插件后续可以调用模板。

模板不是简单 prompt，而是一个可计费、可路由、可追踪、可版本化的业务任务。

## 模板目标

- 降低用户 prompt 门槛。
- 把成功项目流程沉淀下来。
- 让模型调用可控。
- 让点数定价可配置。
- 让任务结果可复用。
- 支持后续插件和 Agent 调用。

## 模板结构

模板应包含：

- template_id
- name
- description
- task_type
- input_schema
- output_schema
- required_context
- workflow_steps
- model_route
- pricing_rule
- version
- enabled

## 输入 Schema

输入 Schema 用于驱动桌面端表单和 API 校验。

示例：

```json
{
  "topic": {
    "type": "string",
    "required": true,
    "label": "主题"
  },
  "platform": {
    "type": "enum",
    "required": true,
    "options": ["小红书", "抖音", "公众号", "视频号"]
  },
  "count": {
    "type": "number",
    "default": 4,
    "min": 1,
    "max": 12
  }
}
```

## 上下文

模板可以声明需要读取哪些上下文。

可用上下文：

- project_brief
- brand_kit
- customer_profile
- reference_assets
- previous_outputs
- platform_rules
- user_instruction

示例：

```json
{
  "required_context": ["project_brief", "brand_kit"],
  "optional_context": ["reference_assets", "previous_outputs"]
}
```

## 工作流步骤

工作流步骤可以由多个模型调用、数据处理和资产生成组成。

步骤类型：

- prompt
- llm_call
- vision_call
- image_generation
- image_editing
- video_generation
- asset_save
- credit_checkpoint
- safety_check
- output_format

示例：

```json
[
  {
    "step": "analyze_brief",
    "type": "llm_call",
    "route": "strategy_model"
  },
  {
    "step": "generate_cover_prompts",
    "type": "llm_call",
    "route": "copy_model"
  },
  {
    "step": "generate_images",
    "type": "image_generation",
    "route": "image_model"
  },
  {
    "step": "save_outputs",
    "type": "asset_save"
  }
]
```

## 输出 Schema

输出应结构化，方便保存、展示、导出和再次调用。

示例：

```json
{
  "creative_directions": [
    {
      "name": "string",
      "concept": "string",
      "visual_prompt": "string",
      "copywriting": "string"
    }
  ],
  "assets": ["asset_id"],
  "credits": {
    "estimated": "number",
    "actual": "number"
  }
}
```

## 模板版本

模板必须支持版本。

原因：

- prompt 会迭代。
- 模型路由会变化。
- 点数价格会变化。
- 用户历史任务需要追溯当时使用的模板版本。

要求：

- 已发布版本不可直接修改。
- 修改后生成新版本。
- 任务记录保存 template_id 和 version。
- 支持灰度发布。

当前 MVP 实现：

- `task_type + version` 唯一。
- Admin Console 可创建模板草稿或直接发布模板。
- `POST /api/admin/workflow-templates/{template_id}/publish` 会发布目标版本。
- 同一个 `task_type` 任意时刻只保留一个已发布版本；发布新版本会自动停用旧版本。
- 任务执行时保存实际使用的 `template_id` 和 `template_version`。
- 灰度发布仍是后续能力，第一阶段不做半发布状态。

## 推荐 MVP 模板

### 1. 客户 brief 分析

用途：

- 把客户输入整理为可执行创作方向。

输出：

- 项目目标
- 受众
- 风格建议
- 内容方向
- 风险点

### 2. 品牌风格提取

用途：

- 从 logo、历史素材和品牌介绍中提取风格。

输出：

- 色彩
- 字体气质
- 视觉关键词
- 文案口吻
- 禁忌
- style_prompt

### 3. 三套创意方向

用途：

- 为客户提案生成多个方向。

输出：

- 方向名
- 核心概念
- 主视觉提示词
- 标题方向
- 适用平台

### 4. 小红书封面批量生成

用途：

- 快速生成多张封面候选。

输出：

- 封面图
- 标题变体
- 风格说明
- 导出尺寸

### 5. 短视频脚本和分镜

用途：

- 从主题生成可执行视频脚本。

输出：

- 开头钩子
- 脚本
- 分镜
- 镜头描述
- 画面提示词
- 封面标题

## 后台管理

Admin Console 应支持：

- 创建模板。
- 编辑草稿版本。
- 发布模板。
- 禁用模板。
- 配置模型路由。
- 配置点数规则。
- 查看模板成功率。
- 查看模板平均成本。
- 查看用户反馈。

## 不推荐

- 把模板写死在桌面端。
- 只存 prompt，不存输入输出结构。
- 任务不记录模板版本。
- 所有模板统一扣点。
- 没有灰度和回滚。
