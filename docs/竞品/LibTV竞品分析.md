# LibTV竞品分析

## 定位

LibTV 是面向 AI 视频创作的专业工作台，公开资料中反复强调“无限画布 + 节点式工作流 + 多模型聚合 + Agent Skill/API”。它不是单次视频生成工具，而是把剧本、分镜、图片、视频、音频和导出流程放进同一个工作空间。

对 Reveria 来说，LibTV 是最重要的“视频生产工作流”方向竞品。

## 核心能力

### 1. 无限画布

LibTV 使用无限画布组织文本、图片、视频、音频和脚本节点，让创作者能看到整个视频项目结构。

启发：

- 视频项目不适合只用线性表单。
- Reveria 后续需要支持空间化组织素材、分镜和版本。
- MVP 可以先做项目任务流，第二阶段再引入无限画布。

### 2. 节点式工作流

LibTV 把剧本、角色、分镜、画面、视频、音频等拆成节点，并支持连线、复用和局部重生成。

启发：

- 高级视频创作需要可控的中间过程。
- 普通用户不应直接面对复杂节点。
- Reveria 可以让内部运营和高级用户使用工作流编辑器，普通用户使用模板入口。

### 3. 剧本到分镜到成片

LibTV 的核心链路是从创意和脚本出发，生成结构化分镜，再生成视频片段和成片。

启发：

- Reveria 的视频能力应先从脚本、分镜和封面开始。
- 视频生成不是第一版必须完整解决的问题。
- 分镜、角色、场景、镜头和字幕应该成为可管理资产。

### 4. 角色一致性和专业控制

公开资料中提到 LibTV 支持角色三视图、多角度、分镜、多机位、灯光运镜、视频提帧、高清处理等专业能力。

启发：

- 角色一致性是视频创作的核心痛点。
- Reveria 后续应建立角色库和场景库。
- 对短剧、广告和品牌视频，需要把角色、产品和场景固定下来。

### 5. 多模型聚合

LibTV 聚合多个主流视频、图像和语言模型，让用户在一个平台里完成视频流程。

启发：

- Reveria 的模型策略是正确的：不自研基础模型，接入最强上游。
- 模型供应池必须可替换。
- 管理后台要能控制模型、价格、并发和可用范围。

### 6. Agent Skill/API

LibTV 公开资料中强调双入口：人类创作者使用网页工作台，AI Agent 通过 Skill/API 自动调用视频能力。

启发：

- Reveria 后续也应支持 Agent/API 调用完整工作流。
- 这能让内部自动化、插件和第三方 Agent 调用 Reveria 的项目交付能力。
- MVP 阶段可以先预留 workflow_template 和 task API。

### 7. 订阅 + 积分制

LibTV 的公开定价资料显示其采用订阅制与积分消耗结合，并把并发任务、存储空间、高质量视频额度等放入套餐权益。

启发：

- Reveria 的商业化不能只卖点数。
- 套餐应该同时管理点数、并发、存储、模型等级、团队成员和高级能力。
- 视频任务需要更严格的成本和风控。

## LibTV 的强项

- 视频工作流完整。
- 无限画布和节点式工作流适合专业控制。
- 多模型聚合降低创作切换成本。
- 角色一致性和分镜能力抓住视频痛点。
- Agent Skill/API 有平台化潜力。
- 订阅 + 积分 + 并发 + 存储的商业组合值得借鉴。

## LibTV 可能的空白

以下是基于公开资料的产品推断，不等同于确定缺陷：

- 更偏视频创作者和 AI 短片/短剧制作。
- 对图文、品牌提案、社媒封面、客户项目交付的覆盖可能不是中心。
- 节点式工作流对普通传媒工作室用户可能仍有学习成本。
- 工作室经营层面的项目预算、客户毛利、成员额度和交付包管理仍有差异化空间。

## Reveria 应吸收的能力

- 无限画布作为后续高级能力。
- 剧本到分镜再到视频的结构化流程。
- 角色库、场景库和产品库。
- 节点工作流作为内部和高级用户工具。
- Agent/API 调用工作流。
- 订阅 + 点数 + 并发 + 存储的套餐设计。

## Reveria 不应照搬的地方

- 不把第一版做成复杂节点视频平台。
- 不把中心放在专业影视制作，而忽略中小传媒工作室的日常图文交付。
- 不让普通用户先学习节点再完成任务。
- 不只解决视频，要同时解决图文、品牌、项目和成本。

## 对 Reveria 的结论

LibTV 把“AI 视频导演/视频工作流”做得很清晰。Reveria 如果要超越它，不应从第一天就正面做完整视频平台，而应该先把工作室项目、品牌库、脚本、分镜、封面和交付包打通。视频生成可以逐步增强，但项目交付系统必须先立住。
