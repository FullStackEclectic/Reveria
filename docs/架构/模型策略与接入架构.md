# 模型策略与接入架构

## 总原则

Reveria 不做基础大模型训练，模型层采用开放、可替换、多租户分销的接入策略，将主流最强的模型作为产品能力来源。

在大方向上，**`12ZX-AI` 网关** 作为核心的模型底座与计费中台，托管所有渠道的 API 密钥及底层接入（包含可灵、即梦等长耗时视频 API，以及 GPT/Claude 等语言模型）。**业务分站**（Go 后端）只需要通过一个统一的站长 API 令牌调用 `12ZX-AI`。

---

## 推荐接入架构

业务分站采用积分点数制时，任何模型密钥都必须处于物理隔离状态，防止客户端被抓包或业务站被入侵时密钥泄露。

正确架构为：

```text
[ Wails 客户端 / 网页端 React 前端 ]
              │
              ▼ 请求业务分站
[ 业务分站 (Go / Wails 后端) ]
  - 校验散客本地点数余额，并提前冻结点数
  - 读取站长后台配置的 12ZX-AI 上游秘钥与网关 URL
              │
              ▼ HTTP API 转发
[ 核心网关层 (12ZX-AI) ]
  - 保存第三方真实 AI 渠道（OpenAI, Gemini, 可灵, 即梦等）的 API Key
  - 计算分站站长 API 令牌的可用额度，扣减批发点数
  - 将多模态任务通过协议适配层，投递给真实 AI 厂商，并处理重试与降级
```

---

## 12ZX-AI 网关的角色定位

我们在项目中指定 `12ZX-AI` 作为核心的模型接入网关与计费中台。

### 网关（12ZX-AI）的职责：
- **渠道统一适配**：处理多模态模型（如 Midjourney、Kling 视频、即梦生图）与常用对话模型的 API 适配与高保真协议转换。
- **健康度与熔断**：实时检测渠道的 Latency 和 429 报错频率，自动屏蔽失效渠道或向高优先级渠道进行 Fallback 降级。
- **高并发流控**：基于 Redis + Lua 脚本防止并发冲突，拦截恶意刷流量。
- **站长充值结算**：管理分站站长的 API Key 账户余额，按调用次数/Tokens/时长进行多维扣费。

### 业务分站（Reveria）的职责：
- **用户体系**：管理分站散客用户的注册、登录（支持网页端微信扫码登录）。
- **画板与协作**：保存项目、无限画布的卡片节点位置、图层关系。
- **分站独立账本**：管理散客本地点数、SaaS 套餐以及扫码充值收单。
- **持久化保存**：AI 任务生成成功后，后台协程异步将原始文件（图片/视频）下载至分站存储目录中，生成缩略图，向前端暴露永久映射 URL。

## 任务执行与状态流转机制

针对快手可灵等视频生成这种**高延迟异步任务**，调用流程采用**轮询+持久化模式**：

```text
1. 散客发起可灵视频生成 
   -> 业务分站冻结该散客 10 点本地积分
   -> 业务分站调用 12ZX-AI 接口，请求 `/v1/video/generations` (使用站长 Key)
2. 12ZX-AI 校验并扣除站长 0.5 美元余额
   -> 12ZX-AI 向可灵官方 API 投递异步生成任务
   -> 12ZX-AI 返回给分站 { "task_id": "upstream_kling_xxx", "status": "processing" }
3. 业务分站将该任务写入 API 侧 `generation_tasks` 表（正式环境为 PostgreSQL）
   -> 分站后台启动 Go 协程，以定时器模式轮询 12ZX-AI 的 `/v1/tasks/upstream_kling_xxx` 状态
4. 12ZX-AI 自动从可灵官方轮询并更新任务状态
   -> 视频生成成功，12ZX-AI 返回任务成功，附带临时 OSS 视频下载链接
5. 业务分站 Go 协程接收到成功状态
   -> 下载临时 OSS 视频文件至分站服务器本地 `/storage/uploads/`
   -> 自动截取视频首帧生成缩略图
   -> 将散客本地冻结积分结算为正式扣除，标记分站本地任务为 succeeded，通知前端 React 刷新画布
```
