# 数据模型设计

## 设计原则

在新的“主站网关 + 独立业务分站”架构中，业务分站的数据模型专注于**画布创作体验、项目资产管理、消费者本地积分结算以及支付订单**，将复杂的“AI通道、服务熔断、多供应商管理”物理隔离至 `12ZX-AI`。

核心原则：
- **网关配置表剥离**：分站数据库不再保存 API 密钥和底层模型配置（即废弃原 `provider`、`model` 实体），全部由分站站长在后台配置主网关 API Key。
- **业务主权独立**：项目、画布、资产、订单和成员依然是业务分站的核心。
- **双重消费对账**：分站的生成任务需要关联主网关的任务 ID 和批发额度消耗，用于分站站长对账和成本利润分析。

---

## 核心实体关系

```text
User / Workspace
  -> Workspace Member (成员与限额)
  -> Project (项目)
       -> Project Canvas (画布)
       -> Asset (图片/视频资产)
       -> Generation Task (生成任务，关联 12ZX-AI 的 upstream_task_id)
  -> Local Credit Ledger (本地点数账本，包括赠送/充值/退款余额)
  -> Orders (微信/支付宝/Stripe 支付订单)
```

## 1. 核心业务表

### user (用户表)
用户登录主体。
- `id` (int/uuid)
- `email` (string)
- `phone` (string)
- `display_name` (string)
- `avatar_url` (string)
- `status` (active / disabled)
- `created_at`
- `updated_at`

### workspace (工作区表)
团队、额度和权限边界。
- `id` (uuid)
- `name` (string)
- `owner_user_id`
- `plan_id` (关联套餐)
- `recharge_balance` (充值点数)
- `gift_balance` (赠送点数)
- `refund_balance` (退款点数)
- `storage_quota` (存储配额字节)
- `created_at`
- `updated_at`

### workspace_member (工作区成员)
- `id`
- `workspace_id`
- `user_id`
- `role` (owner / admin / manager / creator / viewer)
- `daily_credit_limit` (成员每日额度)
- `monthly_credit_limit` (成员每月额度)
- `status`
- `joined_at`

---

## 2. 项目与画布表

### project (项目)
- `id` (uuid)
- `workspace_id`
- `name` (string)
- `brief` (string)
- `status` (draft / active / reviewing / delivered / archived)
- `budget_credits` (项目预算)
- `consumed_credits` (项目已消耗点数)
- `created_by`
- `created_at`
- `updated_at`

### project_canvases (项目无限画布)
存储项目的无限画布元数据、卡片节点位置和自定义样式。
- `project_id` (主键)
- `workspace_id`
- `canvas` (画布节点 JSON，记录所有卡片的位置、宽高、文字内容、层级等)
- `updated_by`
- `created_at`
- `updated_at`

### asset (素材/资产库)
包含用户上传素材、AI 生成的图片视频以及导出的作品。
- `id` (uuid)
- `workspace_id`
- `project_id`
- `asset_type` (image / video / audio / text / document)
- `source` (upload / generated / imported / exported)
- `file_url` (指向本地存储或云 S3 存储的永久相对地址，形如 `/api/files/{name}`)
- `thumbnail_url` (相对缩略图地址)
- `metadata` (物理宽高、长宽比、大小、时长等 JSON)
- `created_by`
- `created_at`

---

## 3. 生成任务与计费对账表

### generation_task (生成任务表)
关联用户本地操作、本地点数扣减与主网关异步任务状态。
- `id` (uuid, 分站本地任务 ID)
- `workspace_id`
- `project_id`
- `user_id`
- `task_type` (text_to_image / image_to_video 等)
- `input_payload` (提示词、负向提示词、分辨率、比例等参数 JSON)
- `output_payload` (模型输出的资产链接列表 JSON)
- `selected_model` (调用的模型标识，如 `kling-v1-5`)
- `upstream_task_id` (关联 12ZX-AI 返回的异步生成任务 ID，用于分站后台轮询)
- `estimated_credits` (估算本地点数)
- `frozen_credits` (冻结的本地点数，包含分站的赠送/充值/退款明细)
- `actual_credits` (最终结算的本地点数)
- `upstream_cost_credits` (主站实际扣除站长 12ZX-AI API 令牌的额度点数，用于站长核算进货成本)
- `status` (pending / running / succeeded / failed / refunded / cancelled)
- `error_code`
- `error_message`
- `created_at`
- `completed_at`

### credit_transaction (点数流水表)
分站本地积分扣减或增加流水。
- `id`
- `workspace_id`
- `user_id`
- `project_id`
- `task_id`
- `transaction_type` (recharge / freeze / consume / release / refund / adjust_add / adjust_sub)
- `gift_amount` (赠送点数变化值)
- `recharge_amount` (充值点数变化值)
- `refund_amount` (退款点数变化值)
- `balance_after`
- `reason` (关联说明)
- `created_at`

## 4. 商业化与运营表

### plans (订阅套餐表)
- `id` (uuid)
- `name` (标准版 / 专业版)
- `price_cents` (月费，单位分)
- `monthly_credits` (套餐每月赠送额度)
- `max_members` (团队成员限制)
- `storage_quota_bytes` (存储限制)
- `enabled` (是否启用)

### orders (充值/订阅订单表)
- `id` (uuid)
- `workspace_id`
- `plan_id` (可选，关联套餐)
- `amount_cents` (订单实际支付金额，单位分)
- `payment_provider` (wechat / alipay / stripe)
- `status` (pending / paid / failed / cancelled)
- `created_at`
- `updated_at`

### client_settings (分站站长配置表)
单体化部署或分站独立部署时，站长用于配置与主站的鉴权连接。
- `id` (主键)
- `upstream_api_url` (主网关地址，如 `https://api.12zx.com`)
- `upstream_api_key` (站长在主网关充值后申请的开发者 API Token)
- `allow_user_register` (是否开放注册)
- `gift_credits_on_register` (新注册用户赠送的点数)
- `price_rate` (对散客定价的加价率，例如默认 1.5 倍)

## 关键注意事项
1. **防爆与熔断设计**：分站向 `12ZX-AI` 发起请求前，若主网关接口返回 402（余额不足），本地分站应当在毫秒级退回散客已冻结的本地点数，并中止状态变更。
2. **文件永久化存储**：视频与图片生成完成后，由于 `12ZX-AI` 等中转网关不会永久保存超大文件，分站后端协程必须立刻将 `output_payload` 里的原始图片或视频文件下载至本地 `/storage/uploads/` 中，并生成缩略图，更新 `asset` 记录后才可将生成任务标记为 `succeeded`。
3. **高并发事务保护**：分站扣减积分需基于 Gorm 事务，使用 `SELECT FOR UPDATE` 锁定 `workspace` 额度行，防止并发扣点产生“负钱包”漏洞。
